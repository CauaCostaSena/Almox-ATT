ALMOX 3.2 — ATUALIZAÇÃO A PARTIR DAS ANOTAÇÕES DA EQUIPE

PARA ATUALIZAR O ALMOX 3.1 QUE JÁ TEM DADOS
1. Pare o site com Ctrl+C. Faça uma cópia de segurança do banco no Workbench.
2. Extraia o ZIP 3.2 em outra pasta. Abra no VS Code a pasta com package.json.
3. No terminal, execute um comando de cada vez:
   npm ci
   npm run setup:env
4. Copie a configuração de conexão da versão anterior para o .env desta pasta.
   O nome do arquivo é exatamente .env, ao lado de package.json.
   Não altere apenas .env.example: esse arquivo é o modelo.

   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_NAME=almox
   DB_USER=root
   DB_PASSWORD=
   PORT=3000

   Use o nome exato do banco que você já utiliza (por exemplo almox_v3).
   DB_PASSWORD= fica vazio somente se seu MySQL realmente não tiver senha.
5. Com o MySQL ativo, execute:
   npm run db:setup
   npm run build
   npm start
6. Abra http://localhost:3000. Não use Go Live nem abra index.html diretamente.

O db:setup adiciona cidade/bairro, e-mail de autoria e referência do histórico.
Ele não apaga produtos, funcionários ou movimentações. Registros antigos ficam
sem cidade/bairro até o administrador preenchê-los. O comando também recupera
a conta principal e encerra suas sessões para exigir um novo login.

ACESSO ADMINISTRATIVO
Na tela de login, use Acesso do administrador.

Após entrar, aparecem Funcionários e Movimentações de admin.
Uma conta comum não passa a ser admin ao digitar Administrador no cargo.

Se a conta principal ainda não entrar, na pasta 3.2 rode:
   npm run admin:reset
Esse comando recupera somente a conta principal e não apaga dados.
Se houver outro cadastro usando admin@almox.est, ele informa o conflito em vez
de promover esse funcionário automaticamente. Nesse caso o cadastro conflitante
precisa ser revisado pelo responsável no MySQL antes de repetir o comando.

INSTALAÇÃO NOVA
Instale Node.js 24 e MySQL 8.0.16 ou superior, depois siga os passos acima.
O db:setup cria o banco indicado em DB_NAME e a conta principal.
Alternativa: execute no Workbench o arquivo separado Almox_Banco_MySQL_3_2.txt,
que cria almox e almox_testes. Ele serve para instalação nova, não para migrar
uma estrutura antiga. Não contém produtos ou funcionários de demonstração.
O arquivo de banco completo é entregue separado do ZIP do site.
database/schema.sql é apenas a estrutura utilizada pelo preparador do projeto.

REGRAS DO PAINEL RESULTADOS
Todas as saídas são consideradas vendas para esta atividade.
A receita usa preço e quantidade registrados na saída; não muda ao editar o
preço atual do produto. Não é lucro líquido, pois não há campo de custo.
As entradas somam recebimentos e o saldo inicial de cadastros no mês escolhido.
O valor em estoque usa preço atual vezes saldo atual, independente do mês.
Datas dos gráficos usam horário de Brasília. Cadastros antigos já excluídos,
sem referência preservada, só podem ser agrupados pelo nome que restou no log.

E-MAIL EM REGISTROS ANTIGOS
A migração recupera o e-mail atual do autor quando a conta ainda existe.
Se a conta já foi apagada, o log mostra o nome antigo e informa a ausência de
e-mail. A partir desta versão, o e-mail fica preservado na própria movimentação.

SENHA DE EXCLUSÃO
O padrão solicitado é #DeleAll42. Não confundir com a senha de login do admin.
Se for configurá-la no .env, use aspas por causa do caractere #:
   PRODUCT_DELETE_PASSWORD="#DeleAll42"

VERIFICAÇÃO DESTA ATUALIZAÇÃO
   npm run test:changes
Executa somente as verificações novas/corrigidas de 3.2, sem MySQL real.
Não foi reexecutada a suíte das funcionalidades aprovadas pela equipe.
O relatório docs/Atualizacao_3_2.md detalha observações, alterações e limites.

PARA ABRIR OUTRO DIA
Inicie o MySQL, abra o terminal desta pasta e execute npm start.
Não repita db:setup apenas para abrir: ele redefine o acesso administrativo.
